## 安装与使用

### 客户端（必需）

1. 建一个 **Minecraft 1.21.11 + Fabric Loader 0.19.3** 的实例（官方启动器 / Prism / Axolot 等均可）；
2. 把 **Fabric API `0.141.5+1.21.11`**（或该 MC 版本的更新版）放进实例的 `mods/`；
3. 把 **`e33chat-Fabric-1.21.11-3.1.1.jar`** 放进**同一个**实例的 `mods/` 目录；
4. （可选）装 **Mod Menu**，即可获得图形化配置入口；
5. 启动游戏后聊天栏就是本模组的聊天界面，配置界面在 **Mod Menu → E33Chat → 配置**。

> 只需客户端安装。纯原版服 / Paper 服也能用全部**本地**功能，只是跨玩家联动不可用（见下文「服务端联动与网络」）。

### 服务端（可选，装了才有联动）

| 服务端类型 | 装什么 | 效果 |
|---|---|---|
| Fabric 服务端 | 本分支的 `e33chat-Fabric-1.21.11-3.1.1.jar` | 消息元数据 / 引用精确跳转 / @提及同步 / **群聊** / **玩家互动动作**全部可用 |
| Paper 1.21.11 | `paper-plugin/` 构建出的 `E33ChatPaper-3.0.1.jar` | 走同一套自定义载荷线协议，**客户端一行不用改**（见 [`paper-plugin/README.md`](paper-plugin/README.md)） |

### 通道节食（实验性，默认关闭）

位置：**配置界面 → 高级 → 网络与服务端 → 「通道节食（实验性）」**。

开启后，在**非 Fabric 服务器**（如 Paper）上不会把自定义通道声明发给服务端（`brand` 含 `fabric` 的服务器与单机/局域网不受影响），从而规避 Paper 的 `Too many channels registered!` 踢人问题。

> ⚠️ 该开关会同时压制**其它模组**的通道声明（其功能会静默失效），建议仅在进入 Paper 等严格服务端遇踢时临时开启。

## 与原版的主要区别

### 聊天界面

- **主题系统**：暗 / 浅色主题 + 6 种强调色 + 自定义 HEX 配色，配置界面跟随主题
- 保留原版气泡、引用块、表情、图片消息等完整界面
- **右键二级菜单圆角化**：整块面板圆角 + 仅悬停行圆角高亮

### 交互增强

- **聊天文本选择**：鼠标拖选任意已渲染文本，`Ctrl+C` 复制；与链接点击、滚动条拖动互不冲突
- **系统消息可复制**：选中后 `Ctrl+C` 复制；右键系统消息**只显示「复制」**（无引用）
- **聊天输入框**：鼠标拖选、`Ctrl+A` 全选、复制/粘贴/剪切、选中后删除
- **引用块双击跳转**：双击消息里的引用行 → 滚动到被引用原消息并短暂高亮
  - 本地引用精确记录目标；**其他玩家的引用**在服务端安装本模组时通过 hash 链路精确定位，否则退化为内容匹配
- **链接点击**正确打开系统浏览器
- **未知文本 ClickEvent 交回原版处理**（含 1.21.11 的 `Custom` / `ShowDialog`），插件自带的可点击菜单不再「点了没反应」

### 通知与免打扰

- **免打扰（DND）**
  - 左上角月亮按钮，**按会话独立**：公屏一份，每个私聊各自一份
  - 进入私聊视图时，同一按钮自动切换为「该私聊」的开关
  - 免打扰时：不弹灵动岛横幅、静默非 @ 提示音；**@提及 / 引用始终提醒**；**左下角红点保留**
  - 玩家列表中被免打扰的玩家显示**紫色月亮**，名字过长自动截断并加 `...`
- **公屏消息小窗**（聊天面板关闭时）
  - 左下角聊天图标上方显示最近 3 条公屏消息
  - 半透明圆角面板、发送者名与正文异色、长消息多行且不重复名字
  - 新消息从下往上顶、最旧淡出；**静默 5 秒**（设置中可调 1~60，热更新即时生效）后淡出
  - 公屏免打扰时不弹出；跟随 `F1` 隐藏
- **在线人数状态行**：侧边栏底部显示绿色 `【在线N人】`（含自己，与 TAB 口径一致）/ `【单人游戏中】`
- **玩家列表在线状态**：头像右下角小圆点（在线绿 / 离线灰）
- **灵动岛 × DangoMusic 联动**（可选）
  - 与 **DangoMusic（3D 歌词音乐模组）** 同时安装时，顶部灵动岛显示「封面 + 曲名 + 艺术家 + 播放时间（`1:26 / 3:35`）」（3.1.1 起不再画进度条，避免与时间显示重复）
  - **播放中常驻**、**暂停约 1.5 秒后淡出**（与 @ 通知横幅同一动画时长）
  - 可在 **设置 → 「横幅」分组 → 「灵动岛显示音乐」** 关闭（默认开）
  - **未装 DangoMusic 时行为完全不变**；不为其自带的灵动岛让位（如需可关闭 DangoMusic 自带的岛）

### 群聊（方案 A：服务端中继）

> **所有群成员都必须安装 E33Chat**（客户端与服务端是同一个 jar）。群、群成员与群消息全部由
> Fabric 服务端保存/转发，客户端之间不直连、不 P2P。服务端没装 E33Chat 时「+」入口变灰并提示不可用。

- **新建群聊**：侧边栏顶部搜索框（已缩短到约 60% 宽度、靠左）右侧的 **「+」** 圆角按钮 →
  居中面板「添加新群聊」：群名（可留空 → 显示 `【群聊】`）→ 在线玩家勾选列表 → `完成` / `取消`
- **邀请 → 接受 / 拒绝**：被勾选的玩家收到 **「X 邀请你加入群聊【群名】」**（横幅 + 会话内提示行，
  带 **接受** / **拒绝** 按钮）；接受后加入并通知创建者「X 已加入群聊」，拒绝也会回执给创建者
- **被移出 / 被解散**：目标玩家弹横幅「你已被移出群聊 xxx」/「群聊 xxx 已解散」（复用灵动岛横幅，新增 `[群聊]` 类型）
- **侧边栏群会话项**：仿微信 —— 成员头像（**>4 人时取最先的 9 个排 3×3 九宫格**，2~4 人为 2×2，
  1 人为单张大头像）+ 群名（未命名 → `【群聊】`）+ 最后一条消息预览 + 未读红点
- **群聊界面**：与私聊**完全同一套气泡**（颜色/头像/引用/图片/表情/选中复制/滚动手感全部复用），
  标题栏**关闭键左侧**多一颗**齿轮「设置」**按钮
- **群聊设置**（居中面板，与新建群聊同风格）：群名输入 + 保存、成员列表（创建者/本人有标记）、
  逐行「踢出」、底部「添加玩家」（含**成员搜索**）+「解散群聊」（仅创建者，两段确认）/「退出群聊」（非创建者）+「完成」
- **群名/成员变更**：服务端广播新的群快照（`group_sync`），侧边栏与设置界面即时刷新
- 开关：**设置 → 「私聊」分组 → 「群聊」**（默认开启，仅关闭入口展示）

### 玩家互动动作（拍了拍等）

> 右键**其他玩家的头像**即可弹出动作菜单（自己的头像不弹）。公屏 / 群聊 / 私聊三种视图都支持，
> 动作作用范围**按当前会话推导**：公屏 → 全服、群聊 → 该群在线成员、私聊 → 只有你们两人。

- **8 个内置动作**：拍了拍 / 戳了戳 / 捏了捏 / 踢了踢 / 揉了揉 / 喷了喷 / 抱了抱 / 吹了吹
- **自定义**：菜单最底部「自定义」→ 弹小卡片输入一个词条（≤12 字符，**一次性生效，不保存**），
  确定后聊天输入框自动带上前缀，直接输入正文回车即可
- **显示效果**：动作消息渲染成**居中的系统行** `A 拍了拍 B 说：正文`（无气泡、不弹横幅、不参与消息去重），
  与普通聊天在视觉上区分开
- **服务端可选**：
  - 服务端装了本模组 → 走 `e33chat:player_action` 通道转发，**词条由服务端按固定表生成**（客户端无法伪造）
  - 服务端没装（原版 / Paper）→ 自动退化为普通聊天发送，收端按内置词条白名单还原成同一行系统消息
- 「自定义」词条**不参与退化还原**（避免把普通聊天误判成动作），未装服务端的服上只会显示成普通聊天

### 兼容与稳定性

- **Jade（玉）软兼容**：显示 Jade 描述框时，通知横幅自动避让
- **皮肤解析异步化**：消除渲染线程阻塞造成的卡顿
- **主线程卡顿看门狗**：主线程长时间无 tick 时输出诊断日志
- **服务端联动通道按服务器白名单声明 + 自愈**（见下节）

## 服务端联动与网络（重要）

本模组在服务端安装时可以启用**消息元数据、精确引用跳转（含其他玩家的引用）、私聊增强、@提及同步**等联动功能。

### 为什么需要「白名单」

自定义载荷通道的声明发生在**配置阶段**，而那一刻客户端**无法得知服务端是否也装了本模组**（协议不下发模组列表）；同时，所有模组声明的通道会被合并成一张清单发给服务端，某些服务端（如 Paper）对这张清单的**数量**有硬上限。

因此采用「**按服务器记忆** + **按连接注册**」策略：

| 场景 | 是否声明本模组通道 | 联动 |
|---|---|---|
| 单机 / 自己开局域网 | ✅ 是 | 全部可用 |
| 局域网（私有地址） | ✅ 是 | 全部可用 |
| **已记住的 E33Chat 服务器** | ✅ 是 | 全部可用 |
| 其它远程服务器（Paper / 原版 / 未装本模组的服） | ❌ **否（0 个通道）** | 不可用（本地功能不受影响） |

关键点：

- **按连接注册/注销**：每次连接重新判定，断开即清理，不会把上一台服务器的通道残留带到下一台
- **自动记忆、自愈**：第 1 次进入某服务器后，若检测到服务端也装了本模组，就把地址写入 `config/e33chat/e33chat-servers.txt`；**第 2 次连接起**自动声明通道（首次连服受协议时序限制，无法当场启用）。服务端后来移除本模组，也会自动忘记该服务器
- 玩家**无需手动维护**任何文件
- 兜底开关：在 `config/e33chat/` 下放置空文件 `no-custom-channels.flag` 可**完全关闭**通道声明（联动随之不可用）

### Paper 服务端的「通道数量上限」（与白名单是两个问题）

Paper（及部分严格服务端）对客户端声明的**通道总数**有硬上限，超限时报：

```
Couldn't handle custom payload on channel minecraft:register
java.lang.IllegalStateException: Cannot register channel. Too many channel registered!
→ 客户端被踢：Invalid custom payload payload!
```

这通常是**整合包整体通道数超限**（模组越多越容易触发），本模组只占其中 13 个；由于非白名单服务器我们不声明任何通道，**本模组不会成为超限的推手**。

**服务端侧解决方案**（需要服主操作）：给服务端启动参数加上

```
-Dpaper.disableChannelLimit=true
```

### 引用同步是怎么工作的

- 客户端引用消息时发送 `quote_sync`（含消息 hash、被引用消息 hash、被引用者与内容）
- **服务端收到后立即广播** `chat_meta` 给所有在线玩家（不再依赖聊天事件，因此离线模式/未签名聊天同样有效）；以 `UUID|msgHash` 做 10 秒去重，避免与聊天事件兜底路径重复广播
- 其他客户端按消息 hash 匹配消息，匹配不上就先挂起（10 秒 TTL），等消息到达后自动挂上
- 一条消息即使先到达/后到达都能正确渲染引用

## paper-plugin（Paper 服务端插件）

`paper-plugin/` 是独立的 Gradle 子项目（不在根构建里），产物为 **Paper 1.21.11** 服务端插件 **E33ChatPaper 3.0.1**：

| 项目 | 值 |
|---|---|
| 目标服务端 | Paper 1.21.11 |
| 产物 | `paper-plugin/build/libs/【paper端】E33ChatPaper-3.0.1.jar` |
| 大小 | **15,028 B**（加入 @提及跨玩家同步前为 11,456 B） |
| 作用 | 引用同步（C2S `e33chat:quote_sync` → S2C `e33chat:chat_meta` 广播）+ @提及同步（`AsyncChatEvent` 解析 `@名字`） |

线格式与 Fabric 侧逐字节一致（34 项离线校验全通过），客户端无需任何改动；字段表与构建方式见 [`paper-plugin/README.md`](paper-plugin/README.md)。

## 已知限制

- **首次**连接某个 E33Chat 服务器时不会立即启用联动（协议时序限制），**重连一次**即可生效
- 纯插件服 / 原版服无法提供完整的私聊联动，客户端只能按文本格式推断
- 引用精确跳转：本地引用精确；他人引用在服务端安装本模组时精确，否则按内容就近匹配（内容完全相同的多条消息可能落到邻近那条）
- 公屏小窗只在聊天面板关闭时显示
- 免打扰的横幅/声音拦截仅作用于本模组的通知系统（不影响原版与其它模组）
- **玩家互动动作**：只对**其他玩家**的头像生效（自己发的消息不弹菜单）；服务端没装本模组时
  退化为普通聊天（只有 8 个内置词条能被还原成系统行，自定义词条会显示成普通消息）；`paper-plugin/`
  目前**不转发**动作消息（Paper 服上动作一律走退化路径）

### 群聊（MVP）的限制

- **所有群成员都必须装 E33Chat**，且服务端必须是 **Fabric + 本模组**；Paper / 原版服务端没有群聊后端
  （属于预期，不是 bug）。Paper 客户端仍可用聊天本体，但「+」按钮会提示不可用
- **群状态按世界保存**在 `<世界>/serverconfig/e33chat-groups.json`（服务端内存里是唯一事实来源）。
  换世界 = 换一套群；同一服务端多世界之间不共享
- **离线成员收不到群消息**（无离线补发/离线红点）；重新上线后只补发「群快照」，不补历史消息
- **首次**连接远程 E33Chat 服务器时客户端尚未申报群聊通道（与本模组其它联动的白名单机制一致），
  **重连一次**后群聊才生效；单机 / 局域网 / localhost 首次即生效
- 群消息的**引用块只在发送者本机可见**（服务端不解析群消息内容）；图片/表情/贴图链接照常转发
- 群人数上限 64（协议 `GroupWire.MAX_LIST`）；群名最长 32 字符、单条消息 512 字符
- 权限（按角色）：**邀请 / 解散只有创建者**；**改名 / 踢人对所有成员开放**（但任何人都不能踢创建者）
- 客户端不落盘群成员表（以服务端快照为准），所以**必须连上带本模组的服务端**才看得到群
